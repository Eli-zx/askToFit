## 一、通用约定

| 项 | 说明 |
|---|---|
| Base URL | `http://<host>:8000/api` |
| 编码 | UTF-8；JSON 请求使用 `application/json` |
| 认证 | `Authorization: Bearer <access_token>` |
| 时间 | ISO 8601 字符串；数据库内为 UTC |
| 请求追踪 | 响应头 `X-Request-ID`，未传时服务端生成 |
| 限流 | 超限返回 429，`detail` 说明稍后重试 |
| 错误格式 | 业务错误 `{"detail": "中文说明"}`；参数校验错误为 FastAPI 422 结构 |

需要认证的接口在缺少或使用无效 token 时返回 401；权限不足返回 403。

### 1.1 角色与可见范围

| 角色 | 能力 |
|---|---|
| 未登录 | 仅验证码、登录、注册、问答选项、解析器选项、健康检查、指标 |
| 登录用户 | 自己的会话；自己的知识库（可写）；公开知识库（只读） |
| 管理员（`is_admin=true`） | 登录用户全部能力 + 全部用户的知识缺口接口 + 评估看板接口 |

说明：公开知识库对其他登录用户只读，不能上传、修改、删除、重建索引。

### 1.2 分页约定

| 场景 | 参数 | 默认 |
|---|---|---|
| 会话消息 | `limit` | 50（1–200） |
| 分块预览 | `page`、`page_size` | 1、20（1–100） |
| 知识缺口 | `limit`、`offset` | 50、0 |
| 评估运行 | `limit`、`offset` | 20、0 |
| 评估逐题 | `limit`、`offset` | 50、0 |

## 二、认证

### 2.1 获取图形验证码

`GET /api/auth/captcha`（无需登录）

响应 `200`：

```json
{
  "captcha_id": "5f0c...e9",
  "image": "data:image/png;base64,...",
  "expires_in": 300
}
```

`image` 为 data URL，前端直接放入 `<img>`。验证码默认 4 位，5 分钟过期，一次性使用。

### 2.2 注册

`POST /api/auth/register`（无需登录）

```json
{
  "username": "alice",
  "password": "secret123",
  "confirm_password": "secret123",
  "captcha_id": "5f0c...e9",
  "captcha_code": "A1B2"
}
```

约束：

- 用户名 3–32 位，仅字母、数字、下划线，服务端转小写；
- 密码 6–64 位，且 UTF-8 不超过 72 字节；
- 两次密码必须一致；
- 验证码不区分大小写。

响应 `201`：

```json
{
  "id": 1,
  "username": "alice",
  "nickname": "alice",
  "is_admin": false,
  "created_at": "2026-10-18T08:00:00"
}
```

错误：400 验证码错误或过期；409 账号已存在；429 注册过于频繁。

### 2.3 登录

`POST /api/auth/login`（无需登录）

```json
{
  "username": "alice",
  "password": "secret123",
  "captcha_id": "5f0c...e9",
  "captcha_code": "A1B2"
}
```

响应 `200`：

```json
{
  "access_token": "<JWT>",
  "token_type": "bearer",
  "expires_in": 86400,
  "user": {
    "id": 1,
    "username": "alice",
    "nickname": "alice",
    "is_admin": false,
    "created_at": "2026-10-18T08:00:00"
  }
}
```

错误：400 验证码错误；401 账号或密码错误；403 账号被禁用；429 登录尝试过多。

### 2.4 当前用户

`GET /api/auth/me`（需登录）

响应 `200`：与登录响应中的 `user` 相同。

```json
{ "status": "ok", "app": "AskToFit 售前智能导购", "version": "0.2.0" }
```

## 四、知识库与文档

### 4.1 解析器可用性

`GET /api/parsers/options`（无需登录）

```json
{
  "auto": {
    "available": true,
    "label": "标准解析",
    "description": "内置轻量解析，适合文本型 PDF、Markdown 与常规 Office 文档"
  },
  "mineru": {
    "available": false,
    "label": "深度解析（MinerU）",
    "description": "复杂表格、扫描件、多栏排版识别更准确，解析耗时更长",
    "image": "asktofit-mineru:cpu",
    "reason": "Docker 不可用或镜像未就绪"
  }
}
```

### 4.2 创建知识库

`POST /api/knowledge_bases`（需登录）

```json
{
  "name": "服装售前知识库（2026 春夏）",
  "description": "售前政策与商品资料",
  "embedding_mode": "hybrid",
  "chunk_size": 500,
  "chunk_overlap": 80,
  "is_public": false
}
```

| 字段 | 必填 | 约束 | 默认 |
|---|---|---|---|
| `name` | 是 | 1–100 字，同一用户内唯一 | — |
| `description` | 否 | ≤500 字 | null |
| `embedding_mode` | 否 | `dense` / `hybrid` | `hybrid` |
| `chunk_size` | 否 | 100–2000 | 500 |
| `chunk_overlap` | 否 | 0–1000，且小于 `chunk_size` | 80 |
| `is_public` | 否 | 是否公开 | false |

响应 `201`：`KnowledgeBaseOut`（见下）。错误：409 同名知识库已存在。

### 4.3 知识库列表与详情

`GET /api/knowledge_bases`（需登录）→ `200`，返回自己的和公开的知识库数组。

`GET /api/knowledge_bases/{kb_id}`（需登录，自己的或公开的）→ `200`。

`KnowledgeBaseOut`：

```json
{
  "id": 7,
  "owner_id": 1,
  "name": "服装售前知识库（2026 春夏）",
  "description": "售前政策与商品资料",
  "embedding_mode": "hybrid",
  "chunk_size": 500,
  "chunk_overlap": 80,
  "document_count": 9,
  "is_public": true,
  "created_at": "2026-10-01T09:00:00",
  "updated_at": "2026-10-18T09:00:00"
}
```

错误：404 知识库不存在（包括无权访问，避免泄露存在性）。

### 4.4 更新知识库

`PATCH /api/knowledge_bases/{kb_id}`（仅创建者）

```json
{ "name": "新名称", "description": "新描述", "is_public": true }
```

字段均可选。响应 `200`：`KnowledgeBaseOut`。错误：403/404（非创建者按 404 处理）、409 同名。

### 4.5 删除知识库

`DELETE /api/knowledge_bases/{kb_id}`（仅创建者）→ `204`

行为：先删 Milvus 向量，再删 MySQL 分块、父块、文档、知识库，清理上传目录，最后失效检索/BM25 缓存。Milvus 清理失败返回 `502`，不会留下“数据库已删、向量还在”的中间状态。

### 4.6 上传文档

`POST /api/knowledge_bases/{kb_id}/documents`（仅创建者，`multipart/form-data`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | 支持 pdf/ppt/pptx/md/markdown/doc/docx/png/jpg/jpeg |
| `chunk_size` | int | 否 | 100–2000，默认取知识库 |
| `chunk_overlap` | int | 否 | ≥0 且小于切块大小 |
| `embedding_mode` | string | 否 | `dense` / `hybrid` |
| `force_new` | bool | 否 | 跳过判重，强制作为新文档 |
| `parser` | string | 否 | `auto` / `mineru` |

响应 `202`：`DocumentOut`，文档状态为 `pending`，后台异步解析入库。

```json
{
  "id": 21,
  "kb_id": 7,
  "original_name": "物流仓配与时效说明.md",
  "file_type": "md",
  "file_size": 18342,
  "status": "pending",
  "error_message": null,
  "chunk_count": 0,
  "chunk_size": 500,
  "chunk_overlap": 80,
  "embedding_mode": "hybrid",
  "parser": "auto",
  "version": 1,
  "is_current": true,
  "update_action": "pending",
  "similar_doc_id": null,
  "similar_doc_name": null,
  "similarity": null,
  "replaces_doc_id": null,
  "created_at": "2026-10-18T09:00:00",
  "updated_at": "2026-10-18T09:00:00"
}
```

错误：400 格式不支持/参数非法/MinerU 不可用；404 知识库不存在或无权；413 超过 `MAX_UPLOAD_MB`；502 仅出现在删除向量时。

文档状态流转：

```text
pending → processing → completed
                    ↘ failed
                    ↘ skipped（内容未变化，自动跳过）
```

`update_action`：`pending` / `created` / `updated` / `unchanged` / `reindexed` / `reindex_failed` / `create_failed` / `update_failed`。

### 4.7 文档列表与详情

`GET /api/knowledge_bases/{kb_id}/documents`（自己的或公开的）

| 查询参数 | 说明 |
|---|---|
| `status` | 按状态过滤，如 `completed` |
| `include_history` | 是否包含历史版本，默认 false |

→ `200`，`DocumentOut[]`，按创建时间倒序。

`GET /api/documents/{doc_id}`（自己的或公开的）→ `200`，`DocumentOut`。

### 4.8 重新解析入库

`POST /api/documents/{doc_id}/reindex`（仅创建者）→ `202`，`DocumentOut`

约束：

- 历史版本或已跳过文档不能重建；
- `processing` 状态返回 409；
- 原始文件丢失返回 400；
- 重建失败时保留旧分块与向量，文档标记 `reindex_failed`，检索不受影响。

### 4.9 删除文档

`DELETE /api/documents/{doc_id}`（仅创建者）→ `204`

先删向量再删数据库与文件，最后失效缓存。向量清理失败返回 `502`。

### 4.10 分块预览

`GET /api/documents/{doc_id}/chunks`（自己的或公开的）

| 查询参数 | 默认 | 说明 |
|---|---|---|
| `page` | 1 | 页码 |
| `page_size` | 20 | 每页 1–100 |
| `keyword` | — | 正文包含匹配 |

响应 `200`：

```json
{
  "total": 86,
  "page": 1,
  "page_size": 20,
  "items": [
    {
      "uid": "a1b2...",
      "doc_id": 21,
      "kb_id": 7,
      "chunk_index": 0,
      "parent_uid": "c3d4...",
      "content": "……",
      "title": "物流仓配与时效说明",
      "section": "一、发货时效",
      "page": 1,
      "char_count": 486,
      "parent_index": 0,
      "parent_content": "……",
      "created_at": "2026-10-18T09:01:00",
      "updated_at": "2026-10-18T09:01:00"
    }
  ]
}
```

### 4.11 父分块列表

`GET /api/documents/{doc_id}/parents` → `200`，`ParentChunkOut[]`，按 `parent_index` 升序。

### 4.12 分块详情、编辑与删除

- `GET /api/chunks/{uid}` → `200`，`ChunkOut`
- `PATCH /api/chunks/{uid}`（仅创建者）

  ```json
  { "content": "修改后的分块正文" }
  ```

  正文 1–8000 字。保存时重新编码并更新 Milvus，同步父块正文，失效检索缓存。响应 `200`。
- `DELETE /api/chunks/{uid}`（仅创建者）→ `204`，同步删除向量、更新父块和文档分块数。

错误：404 分块不存在或无权；500 编辑时向量更新失败（事务回滚）；502 删除时向量清理失败。

### 5.3 会话列表与详情

- `GET /api/chat/conversations?include_archived=false`（需登录）→ `200`，`ConversationOut[]`，按更新时间倒序。
- `GET /api/chat/conversations/{conversation_id}` → `200`，`ConversationOut`；不是自己的返回 404。

### 5.4 更新会话

`PATCH /api/chat/conversations/{conversation_id}`（需登录）

字段均可选：`title`、`kb_ids`、`model_name`、`temperature`、`top_p`、`max_tokens`、`history_rounds`。响应 `200`。

### 5.5 归档与取消归档

- `POST /api/chat/conversations/{id}/archive` → `200`，`archived_at` 被设置；
- `DELETE /api/chat/conversations/{id}/archive` → `200`，`archived_at` 置空。

归档只影响默认列表展示，不删除消息；超过保留天数后由维护任务自动归档。

### 5.6 删除会话

`DELETE /api/chat/conversations/{conversation_id}`（需登录）→ `204`

删除会话及其全部消息。注意：`knowledge_gaps` 没有外键约束，删除会话不会自动删除对应缺口，需要按 `conversation_id` 单独清理（见[运维与故障排查](运维与故障排查.md)）。

### 5.8 流式提问

`POST /api/chat/conversations/{conversation_id}/messages/stream`（需登录）

请求：

```json
{ "content": "满多少包邮？" }
```

`content` 必填，1–4000 字。

响应：`text/event-stream; charset=utf-8`，响应头包含：

```text
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

流程：

1. 按用户限流（默认 60 次/60 秒）；
2. 校验会话归属与知识库权限；
3. 保存用户消息（首条消息自动以问题前 30 字命名会话）；
4. 读取最近 `history_rounds` 轮历史；
5. 依次推送 `status` → `meta` → 多个 `delta` → `done`，异常时推送 `error`。

SSE 格式：

```text
event: status
data: {"stage":"retrieving","intent":"logistics","intent_confidence":0.9812,"intent_source":"bert"}

event: meta
data: {"conversation_id":39,"intent":"logistics","intent_confidence":0.9812,"intent_source":"bert","rewritten_query":"满多少包邮","sources":[...],"retrieval_strategy":"direct","strategy_source":"rule","retrieval_query_count":1}

event: delta
data: {"content":"满 99 元"}

event: done
data: {"conversation_id":39,"assistant_message_id":102,"content":"……","sources":[...],"intent":"logistics","intent_confidence":0.9812,"intent_source":"bert","rewritten_query":"满多少包邮","latency_ms":12093,"cache_hit":false}
```

事件字段详见[第八节](#八sse-事件详解)。

### 5.9 知识缺口（管理员）

三个接口均需要 `is_admin=true`，普通用户返回 `403 {"detail": "需要管理员权限"}`；管理员可查看并处理所有用户的记录。

- `GET /api/chat/knowledge-gaps`（管理员，返回全部用户）

  | 参数 | 默认 | 说明 |
  |---|---|---|
  | `limit` | 50 | 1–200 |
  | `offset` | 0 | ≥0 |
  | `status` | all | `all` / `open` / `resolved` / `ignored` |
  | `intent` | — | 意图过滤 |
  | `q` | — | 问题模糊匹配 |
  | `user_id` | — | 提交人过滤；缺省返回全部用户 |

  响应 `200`：`KnowledgeGapOut[]`。

- `GET /api/chat/knowledge-gaps/stats?days=14`

  响应 `200`：

  ```json
  {
    "total": 12,
    "open": 5,
    "resolved": 4,
    "ignored": 3,
    "by_intent": [{ "key": "logistics", "label": "物流", "count": 6 }],
    "by_date": [{ "key": "2026-10-18", "label": "2026-10-18", "count": 2 }],
    "by_user": [{ "user_id": 3, "username": "alice", "total": 7, "open": 3 }],
    "top_questions": [{ "key": "支持以旧换新吗", "label": "支持以旧换新吗", "count": 3 }]
  }
  ```

- `PATCH /api/chat/knowledge-gaps/{gap_id}`

  ```json
  { "status": "resolved", "note": "已补充到物流文档" }
  ```

  `status` 为 `open` / `resolved` / `ignored`，`note` ≤1000 字。响应 `200`。

`KnowledgeGapOut` 关键字段：`id`、`user_id`、`username`（提交人）、`question`、`intent`、`intent_confidence`、`intent_source`、`kb_ids`、`best_score`、`vector_score`、`rerank_score`、`retrieval_mode`、`status`、`note`、`resolved_at`、`created_at`。前端缺口运营台按 `username` 分组展示，并可用 `user_id` 或用户快捷标签筛选。

## 六、知识缺口

接口路径与参数见 [5.9](#59-知识缺口)。补充说明：

- 缺口只在“检索有结果但全部被阈值过滤”或“完全没有结果”时记录；
- `best_score` / `rerank_score` / `vector_score` 分字段保存，避免不同量纲混用；
- `retrieval_mode` 取值 `rerank` / `vector` / `none`；
- `status` 默认 `open`，标记 `resolved` 时写入 `resolved_at`，改回其他状态时清空。

## 八、SSE 事件详解

| 事件 | 时机 | 字段 |
|---|---|---|
| `status` | 意图识别完成、开始检索 | `stage`（固定 `retrieving`）、`intent`、`intent_confidence`、`intent_source` |
| `meta` | 检索与过滤完成、调用 LLM 前 | `conversation_id`、`intent`、`intent_confidence`、`intent_source`、`rewritten_query`、`sources`、`retrieval_strategy`、`strategy_source`、`retrieval_query_count` |
| `delta` | LLM 每产出一段文本 | `content` |
| `done` | 回答完成并落库 | `conversation_id`、`assistant_message_id`、`content`、`sources`、`intent`、`intent_confidence`、`intent_source`、`rewritten_query`、`latency_ms`、`cache_hit` |
| `error` | 检索失败、LLM 失败、空回答等 | `message` |

### 8.1 sources 结构

```json
{
  "chunk_uid": "a1b2...",
  "parent_uid": "c3d4...",
  "doc_id": 21,
  "kb_id": 7,
  "version": 1,
  "title": "物流仓配与时效说明",
  "section": "四、运费标准",
  "page": 1,
  "score": 0.9142,
  "content": "……（最多 400 字）"
}
```

- 最多 5 条；
- `score` 是当前最终排序分（通常为重排序分）；
- `content` 是父块正文的截断，不是完整提示词上下文。

### 8.2 策略字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `retrieval_strategy` | `direct` / `hyde` / `subquery` / `backtrack` | 实际执行策略 |
| `strategy_source` | `rule` / `llm` / `fallback` / `disabled` | 策略来源 |
| `retrieval_query_count` | 整数 | 实际召回使用的查询数 |

额外查询文本（HyDE 假设答案、子查询）**不会**通过 SSE 返回给前端，只写 debug 日志。

### 8.3 客户端处理建议

- 按 `\n\n` 分帧，不要假设一个网络 chunk 只包含一个事件；
- 以 `event:` 行决定类型，`data:` 行 JSON 解析；
- 收到 `done` 后关闭连接；收到 `error` 后展示消息并允许重试；
- 浏览器 `EventSource` 不支持 POST，前端使用 `fetch` + `ReadableStream`；
- 不要把 `meta` 当最终答案，最终内容以 `done.content` 为准（或自行拼接 delta）。

## 九、错误码速查

| 状态码 | 典型场景 |
|---|---|
| 400 | 参数非法、验证码错误、知识库为空、文件格式不支持、MinerU 不可用 |
| 401 | 未登录、token 无效或过期、账号密码错误 |
| 403 | 非管理员访问评估接口、账号被禁用 |
| 404 | 会话/知识库/文档/分块/缺口/评估运行不存在，或无权访问 |
| 409 | 同名知识库、账号已注册、文档正在处理 |
| 413 | 上传文件超过 `MAX_UPLOAD_MB` |
| 422 | 请求体字段校验失败（FastAPI 自动生成） |
| 429 | 登录/注册/问答触发限流 |
| 500 | 服务内部错误（分块编辑失败等） |
| 502 | Milvus 向量清理失败 |
