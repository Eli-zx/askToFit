## 1. 项目定位

AskToFit 是一个可私有化部署的电商售前知识问答系统：

- 把企业文档（PDF / Word / PPT / 图片 / Markdown）解析、切块、向量化，形成可检索的知识库；
- 用户用自然语言提问，系统先检索资料、再让大模型组织答案，并给出可展开的引用出处；
- 检索不到可靠资料时不硬编，明确提示未命中，并把问题沉淀到「缺口运营」；
- 提供检索与生成评估看板，用数据判断每次调整是变好还是变差。

一句话介绍：

> **把企业资料变成“有出处、可运营、可量化”的售前问答能力。**

## 2. 角色与页面

| 角色 | 可见页面 |
|---|---|
| 普通用户 | 智能对话、知识库 |
| 管理员 | 以上全部 + 缺口运营、评估看板 |

| 页面 | 作用 |
|---|---|
| 智能对话 | 多知识库问答、流式输出、引用展开、多轮记忆、会话设置；知识缺口抽屉仅管理员可见 |
| 知识库 | 创建知识库、上传与解析文档、分块预览与编辑、重新解析、删除 |
| 缺口运营 | 未命中问题列表、趋势、高频问题、状态流转与备注 |
| 评估看板 | 概览、趋势、运行列表、逐题详情、失败筛选、删除运行 |

登录与注册：

- 注册字段：账号名称（3–32 位字母、数字或下划线）、密码（6–64 位）、确认密码、图形验证码；
- 登录需要账号、密码和图形验证码；
- 注册成功后跳转登录页。

## 3. 启动与准备

### 3.1 本地启动

开发调试：

```bash
uv sync
uv run uvicorn app.main:app --reload --port 8000

cd frontend
npm install
npm run dev
```

**客户演示必须用构建产物 + 单 worker**（不要用 dev 模式，避免 HMR 整页刷新）。演示域名指向 **5173**，构建预览也固定在该端口；端口被占用时 `strictPort` 会直接报错，不会悄悄换端口：

```bash
# 后端：单 worker，不要 --reload
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1

# 前端：先停掉 dev 服务，再构建并用 5173 预览（vite preview 已带 /api 代理）
cd frontend
npm run build
npm run preview -- --host 0.0.0.0 --port 5173
```

常用入口：

| 地址 | 用途 |
|---|---|
| http://127.0.0.1:5173 | 前端入口（演示用构建预览；本地调试时才用 dev，二者不要同时启动） |
| http://127.0.0.1:8000/docs | Swagger 接口文档 |
| http://127.0.0.1:8000/api/health | 健康检查 |
| http://127.0.0.1:8000/api/metrics | Prometheus 文本指标 |

### 3.2 Docker 部署

服务器侧：

```bash
export GHCR_OWNER=<github 用户名或组织>
export IMAGE_TAG=v0.1.0
docker login ghcr.io
docker compose -f docker-compose.deploy.yml pull
docker compose -f docker-compose.deploy.yml up -d
```

说明：

- API 镜像 `ghcr.io/<owner>/asktofit-api`，前端镜像 `ghcr.io/<owner>/asktofit-web`；
- 模型不打进镜像，`./models` 只读挂载到 `/models`；
- MySQL / Redis / Milvus 默认按 `.env` 连接外部服务；
- Web 暴露 80，API 暴露 8000；
- 前端 nginx 已关闭 SSE 代理缓冲并放宽读取超时。

### 3.3 依赖服务与模型

- MySQL 8：默认 `localhost:3306`，库名 `asktofit`
- Milvus 2.4.x：默认 `localhost:19530`（pymilvus 必须是 2.4.x）
- Redis：默认 `localhost:6379`，用于验证码、缓存、限流
- 本地模型：
  - `models/bge-m3`
  - `models/bge-reranker-v2-m3`
  - `models/intent-bert`

模型放在其他位置时，在 `.env` 中设置 `BGE_M3_PATH` / `BGE_RERANKER_PATH` / `INTENT_MODEL_PATH`。

首次启动或首次检索会加载模型，耗时明显，属于正常现象。

### 3.5 设置管理员

```bash
uv run python scripts/set_admin.py --username <账号>
```

或在 `.env` 中配置 `ADMIN_USERNAMES=账号1,账号2`，重启后自动提升（幂等）。

普通账号访问 `/api/evaluations/*` 返回 403；直接访问 `/evaluation` 会被重定向到 `/chat`。

### 3.6 多人线上演示配置（注册/浏览 200 人；同时提问按 20 并发）

复制 `deploy/demo.env.example` 为演示 `.env`，替换账号密码后至少确认：

| 配置 | 演示值 | 作用 |
|---|---|---|
| `MAX_CONCURRENT_LLM` | `16` | 普通用户 LLM 并发 |
| `LLM_ADMIN_SLOTS` | `4` | 管理员独立通道，普通用户占满也不排队 |
| `LLM_ADMIN_QUEUE_TIMEOUT_SECONDS` | `30` | 管理员等待上限 |
| `RATE_LIMIT_REGISTER_REQUESTS` | `500` | 同一场馆出口 IP 也能注册 200 人 |
| `RATE_LIMIT_LOGIN_REQUESTS` | `30` | 登录按 IP + 用户名，互不挤占 |
| `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` | `20` / `40` | SSE 已主动释放连接 |
| `ANSWER_CACHE_TTL` / `RETRIEVAL_CACHE_TTL` | `43200` | 预热缓存保留 12 小时 |
| `MODEL_WARMUP_INTERVAL_SECONDS` | `0` | 关闭空闲保活，避免演示中周期性抢占 CPU |

管理员优先的行为：

- 管理员使用独立的 LLM、重排通道，普通用户满载时仍能拿到槽位；
- 管理员聊天不参与聊天限流，也不受普通流量触发的熔断影响；
- 登录限流发生在鉴权前，管理员同样适用 `RATE_LIMIT_LOGIN_REQUESTS`。

### 3.7 预热演示问题（管理员秒回）

预热会同时写入检索缓存与回答缓存；现场问题必须与预热完全一致
（默认模型、温度 0.3、top_p 0.8、max_tokens 1024、空历史、公共服装库）。

```bash
# 首次预热：普通 FAQ + 管理员演示问题
uv run python scripts/prewarm_demo.py --lane all --admin-username <管理员账号>

# 第二遍校验：断言回答缓存命中，未命中返回非零
uv run python scripts/prewarm_demo.py --lane all --admin-username <管理员账号> --verify

# 清理预热会话，保留缓存
uv run python scripts/prewarm_demo.py --lane all --admin-username <管理员账号> --cleanup
```

问题文件：`data/demo/questions.txt`（30 条普通 FAQ）、
`data/demo/admin_questions.txt`（10 条管理员演示问题）。

## 5. 10 分钟演示脚本

### 第 1 分钟：登录与全貌

1. 用验证码登录演示账号。
2. 用管理员账号带客户浏览顶部导航：智能对话、知识库、缺口运营、评估看板；普通账号只显示前两项。
3. 介绍四个页面的分工：

> 智能对话负责“用知识”，知识库负责“管知识”，缺口运营负责“补知识”，评估看板负责“量效果”。

### 第 2–4 分钟：创建知识库与上传文档

进入「知识库」→ 新建知识库：

- 填写名称、描述；
- 选择可见范围：
  - 私有：仅创建者可查看、检索、上传和管理；
  - 公共：所有登录账号都能查看文档、预览分块并在对话中选择；只有创建者可以编辑、上传、删除和重建索引。
- 选择检索模式：
  - 混合检索：稠密语义 + 稀疏关键词，召回更稳，适合政策文档；
  - 稠密检索：纯语义向量，适合表述多变的问答内容。
- 设置默认切块大小（建议 400–800 字符）与重叠（建议 10%–20%）。

> 检索模式与切块参数在知识库创建后不可修改；单篇文档上传时可以覆盖。

上传文档：

- 支持 PDF、PPT/PPTX、Word（DOC/DOCX）、Markdown、PNG/JPG，单文件上限 50MB；
- 内嵌图片自动 OCR，尺码图、海报等图片文字可检索；
- 扫描件、多栏 PDF、跨页表格可开启「深度解析（MinerU）」；
- 可勾选「强制作为新文档入库」跳过判重。

上传后重点讲三个后台能力：

1. **父子分块**：父块保留完整上下文，子块用于精准检索，命中后自动补全父块内容。
2. **正文判重**：只改标点、格式或文件名不会产生重复文档，状态显示「内容未变化」。
3. **安全版本切换**：正文相似度 ≥ 0.90 视为同一文档的新版本；新版本解析、切块、向量写入、数据库提交全部成功后，旧版本才退出检索。

文档操作：

- 查看解析状态、分块数量、解析参数；
- 「分块预览」可搜索分块并编辑内容，保存后同步更新检索数据；
- 「重新解析」用于解析失败或文档更新；
- 「删除文档」会同时清除分块与向量数据，不可恢复。

### 第 4–7 分钟：问答演示

新建会话：

- 没有会话时直接输入问题并发送，系统会自动用**默认知识库**和默认模型参数创建会话，无需先点「新建对话」；
- 默认知识库优先取**公共的服装售前知识库**（如「服装售前知识库（2026 春夏）」）；民法典等其他知识库不参与默认选择；
- 需要检索其他知识库（或多库检索）、自定义模型/推理参数时，用「新建对话」手动勾选；
- 知识库范围：可多选，演示跨库检索；
- 大模型：DeepSeek V4 Flash（默认）/ DeepSeek V4 Pro / 通义千问 Plus / 通义千问 Max；未配置 Key 的模型会显示「未配置 Key」；
- 推理参数：
  - 温度：越低越严谨，政策类建议 0.1–0.4；
  - Top P：通常保持 0.8 左右；
  - 最长输出 Token；
  - 历史对话轮数：默认 5 轮，0 表示不带历史。

按以下顺序提问，每个问题对应一个卖点：

| 演示问题 | 展示功能 | 讲解要点 |
|---|---|---|
| 满多少包邮？偏远地区运费怎么算？ | 流式输出 + 引用 | 点开「引用 N 条知识库资料」，可看到文档名、章节、页码、分数与原文 |
| 我 165cm、55kg，想买宽松一点的针织衫，选什么码？ | 语义检索 | 能理解身高体重与版型偏好，不是关键词硬匹配 |
| 退货需要保留吊牌吗？运费谁承担？ | 子查询 | 多要素问题自动拆成多个检索查询 |
| 我买大了，又洗过一次，这种情况还能换吗？ | 回溯 | 条件类问题先生成更基础的问题再检索 |
| 怎么判断一件针织衫会不会起球？ | HyDE | 先生成假设答案再检索；假设文本不会进入答案、引用或提示词 |
| 那新疆呢？ | 多轮记忆 | 结合上一轮“偏远地区运费”的上下文回答 |
| 你们支持以旧换新吗？ | 知识缺口 | 资料没有时不硬编，提示未命中，并自动记录缺口 |

补充展示：

- 生成过程中可点暂停按钮停止生成；
- 回答可一键复制；
- 气泡展示意图分类（退换货、发票、物流、支付结算、退款与资金安全、尺码、会员与优惠、商品咨询、问候、综合咨询）及判定来源（本地 BERT / 关键词规则）；
- 无可靠资料时显示「本轮知识库未命中可靠资料」提示。

### 第 7–8 分钟：缺口运营

使用管理员账号进入「缺口运营」（普通账号看不到入口），列表包含所有用户的未命中问题，并按提交人分组、可按用户筛选：

- 查看待处理 / 已解决 / 已忽略统计；
- 按状态、意图、关键词筛选；
- 查看趋势与高频问题；
- 对刚演示的“以旧换新”问题添加备注，并标记已解决、忽略或重新打开。

讲解：

> 知识库不是一次性工程。客户问不到的问题会自动沉淀，形成“发现缺口 → 补充文档 → 再评估”的闭环。

### 第 8–10 分钟：评估看板

演示前先跑好评估（现场直接看结果）：

```bash
# 连知识库校验评估集的文档 / 章节是否存在
uv run python scripts/evaluate_rag.py --validate-only

# 仅检索指标
uv run python scripts/evaluate_rag.py --retrieval-only --limit 10 --strategy auto

# 官方 RAGAS 生成指标（overlay 安装，不修改运行时 .venv）
uv run --with-requirements scripts/eval_requirements.txt \
  python scripts/evaluate_rag.py --limit 5 \
  --judge-metrics faithfulness,answer_relevancy
```

评估脚本默认把结果写入 `eval_runs` / `eval_cases`，同时输出：

- `reports/eval_<timestamp>.json`
- `reports/eval_<timestamp>.md`
- 有生成指标时另输出 `reports/ragas_<timestamp>.csv`

看板讲解顺序：

1. **概览卡**：最近运行状态与时间、doc Hit@K、section Recall@K、Faithfulness；
2. **趋势**：最近多次运行的检索指标走势；
3. **运行列表**：按策略 / 状态筛选，查看数据集、策略、TopK、指标；
4. **详情抽屉**：运行元信息、指标网格、逐题明细；
5. **失败筛选**：只看没答好的题，展开查看问题、期望答案、实际答案、命中摘要与错误；
6. **删除运行**：二次确认后删除运行及明细。

指标口径：

- 检索：doc 级 / section 级的 Hit@K、Recall@K、MRR、NDCG@K；
- 生成：官方 RAGAS 的 Faithfulness、Answer Relevancy、Context Precision、Context Recall；
- 报告会分别标注本地检索指标与 RAGAS 生成指标，不混为一谈。

### 收尾：CI/CD（技术客户）

- CI：每次 push / PR 自动执行后端 pytest、评估集校验、前端 vitest + build、API 与前端镜像构建验证；
- CD：推送 `v*` tag 或手动触发，构建并推送 GHCR 镜像，不自动部署；
- 服务器侧执行 `docker compose pull && up -d` 完成升级。

## 6. 功能明细

### 6.1 文档接入

| 能力 | 说明 |
|---|---|
| 支持格式 | PDF、PPT/PPTX、DOC/DOCX、Markdown、PNG/JPG |
| 图片处理 | PDF / PPTX / DOCX 内嵌图片自动 OCR |
| 旧版 Word | LibreOffice → antiword → OLE 文本提取逐级降级 |
| MinerU | 可选深度解析，独立容器运行；仅 PDF / PPT / PPTX / DOC / DOCX / 图片支持 |
| 文档状态 | 排队中、解析中、已就绪、内容未变化、解析失败 |
| 失败处理 | MinerU 失败时文档标记失败，旧版本继续可检索，不静默降级 |
| 文档操作 | 分块预览、编辑分块、重新解析、删除 |
| 单文件上限 | 50MB |

### 6.2 判重与版本

- 入库前做 NFKC 归一化，去空白、标点、Markdown、HTML、URL，再计算 SHA-256 与 SimHash；
- 只改标点、格式或文件名：识别为内容未变化，状态 `skipped`；
- 正文相似度 ≥ `DOC_DEDUP_SIMILARITY`（默认 0.90）：作为同一逻辑文档的新版本，成功后旧版本退出检索；
- 低于阈值且文件名不同：作为独立新文档入库；
- 上传时可勾选「强制作为新文档入库」；
- 父块、子块和检索结果分别做去重，避免近似资料重复进入提示词。

### 6.3 检索与回答

完整链路：

```text
意图识别（本地 BERT，低置信度回退关键词）
  → 追问改写 / 多轮记忆
  → 策略规划（direct / subquery / backtrack / hyde）
  → 多查询、多模式向量召回（dense / sparse / hybrid）
  → BM25 词法召回（默认与向量结果 RRF 融合）
  → RRF 融合
  → BGE 重排序
  → 分数阈值过滤
  → 父块补全上下文
  → 大模型生成 + 引用
```

多策略规则：

| 策略 | 触发条件 | 示例 |
|---|---|---|
| subquery | 多要素问题：并且、以及、分别、同时、还有、另外、对比、区别、哪个更、两个问号 | 退货要吊牌吗？运费谁承担？ |
| backtrack | 条件/宽泛问题：如果、这种情况、怎么办、能不能、是否可以、遇到，且长度 ≥ 24 | 买大了又洗过，这种情况还能换吗？ |
| hyde | 抽象方法类：为什么、怎么选、如何选择、怎么判断、适合、推荐、介绍，且长度 ≥ 12 | 怎么判断针织衫会不会起球？ |
| direct | 其余问题，尤其是短实体、数字、金额 | 满 199 包邮吗？ |

实现要点：

- 规则优先级：`subquery > backtrack > hyde > direct`；
- LLM 只负责生成子查询 / 回溯问题 / HyDE 假设答案，不参与策略决策；LLM 选择器默认关闭；
- 生成失败、超时或输出为空时自动回退直接检索；
- HyDE 文本只用于向量召回，绝不进入提示词、引用或 `sources`；
- 重排序始终使用原始改写问题，避免丢失金额、时效等约束；
- SSE 的 `meta` 事件返回 `retrieval_strategy`、`strategy_source`、`retrieval_query_count`。

BM25：

- 纯 Python Okapi BM25，不依赖 rank-bm25 / jieba；
- 中文按 unigram + bigram 分词，标题与章节权重高于正文；
- `BM25_MODE=fuse`（默认）：与向量结果一起做 RRF 融合；
- `BM25_MODE=fallback`：仅在向量召回为空或 embedding / Milvus 异常时兜底；
- `BM25_MODE=off`：关闭；
- 每个知识库一份进程内索引，TTL 默认 120 秒；知识库变更后统一失效。

重排序与降级：

- 默认启用 BGE 重排序，候选数 `RERANK_CANDIDATE_K=5`；
- 低于 `RERANK_SCORE_THRESHOLD=0.25` 不作为可靠资料；
- 重排序失败时：
  - `RERANK_FAILURE_MODE=drop`：本轮丢弃资料，回答不带知识库依据；
  - `RERANK_FAILURE_MODE=vector`：退回向量得分继续回答。

### 6.4 会话

- 一个会话可绑定一个或多个知识库；
- 新建时标题留空，按首个问题自动命名；
- 会话列表支持搜索、重命名、删除、归档；
- 已归档会话可恢复；
- 超过 `CONVERSATION_RETENTION_DAYS`（默认 90 天）未更新的会话自动归档；
- 会话设置可修改知识库范围、大模型、温度、Top P、最长输出、历史轮数。

### 6.5 知识缺口运营

触发条件：检索最高分低于阈值且重排未命中。

记录内容：问题、意图、置信度、向量分 / 重排分、检索模式。

页面能力：

- 待处理 / 已解决 / 已忽略统计；
- 按状态、意图、关键词筛选；
- 趋势图与高频问题；
- 标记已解决、忽略、重新打开；
- 填写与编辑处理备注。

### 6.6 评估

评估方式：

- 检索指标：本地纯函数计算，不依赖 RAGAS；
- 生成指标：官方 RAGAS 0.3.0，通过 `scripts/eval_requirements.txt` overlay 安装，不进入运行时 `.venv`。

数据集：

- `data/evaluation/qa_eval.jsonl`，当前 60 条（48 条可回答、12 条不可回答）；
- 字段与判定口径见 `data/evaluation/README.md`；
- 给客户落地时应替换为客户自己的问题集。

命令：

```bash
# 纯文件校验，不连 DB、不依赖 ragas（CI 同款）
uv run python scripts/evaluate_rag.py --validate-dataset

# 连知识库校验文档 / 章节 / 关键词
uv run python scripts/evaluate_rag.py --validate-only

# 仅检索指标
uv run python scripts/evaluate_rag.py --retrieval-only --limit 10

# 指定策略
uv run python scripts/evaluate_rag.py --retrieval-only --limit 10 --strategy direct

# 官方 RAGAS 生成指标
uv run --with-requirements scripts/eval_requirements.txt \
  python scripts/evaluate_rag.py --limit 5 \
  --judge-metrics faithfulness,answer_relevancy

# 只出报告、不写数据库
uv run python scripts/evaluate_rag.py --retrieval-only --limit 10 --no-persist
```

### 6.7 权限与安全

- 注册 / 登录图形验证码；
- 密码 bcrypt 哈希，JWT 鉴权；
- 公共库 / 私有库隔离；
- 提问接口按用户限流：默认 60 次 / 60 秒；登录与注册 10 次 / 60 秒；
- Redis 不可用时限流放行并记录告警；
- 评估 API 全部要求管理员；
- 日志同时输出控制台与文件，报错定位到具体文件与行号。

### 6.8 缓存与监控

- Redis 分层缓存：意图、查询向量、检索结果、完整回答；
- 知识库 / 文档 / 分块变更时统一失效检索与回答缓存，同时清理 BM25 索引；
- 重排序降级结果与空结果使用短 TTL，异常产生的空结果不写缓存；
- `/api/metrics` 输出 Prometheus 文本格式：HTTP 请求量 / 延迟、LLM 调用、检索与缓存命中、策略分布、BM25 等。

## 9. 已知边界

1. **CPU 上首次响应慢**：本地压测实测首 token 约 30 秒级（1 用户、CPU 重排序）。演示前必须预热；高并发生产建议 GPU 或更轻的重排序模型。
2. **首次启动 / 首次检索加载模型**：BGE-M3、重排序模型、意图 BERT 首次加载需要时间。
3. **多 worker 下进程内 BM25 索引各自独立**：靠 TTL 收敛；生产与压测建议单 worker。
4. **单组织部署**：没有多租户 / 组织隔离；多客户共用需额外做租户模型。
5. **登录必须图形验证码**：适合人工使用；系统对接目前没有服务账号 / API Key 机制。
6. **评估集是示例数据**：60 条，对应 9 份服装售前文档；客户落地需替换为客户问题集。
7. **RAGAS 不在运行时依赖**：仅评估 overlay 安装；正常服务与 CI 不需要。
8. **CD 不自动部署**：只构建并推送镜像。
9. **GHCR 包默认私有**：服务器拉取前需要 `docker login ghcr.io`。
10. **MinerU 是可选组件**：镜像 6–10GB，首次使用需提前构建并下载模型。

## 10. 客户价值话术

1. **有据可查**：每个答案都能展开看到文档名、章节、页码、分数与原文，销售可以直接引用。
2. **不硬编**：检索不到可靠资料时明确提示，并把问题沉淀到缺口运营，形成“发现缺口 → 补文档 → 再评估”的闭环。
3. **文档更新安全**：只改标点或文件名不会重复入库；相似文档作为新版本，入库成功后旧版本才下线。
4. **效果可量化**：Hit@K、Recall@K、MRR、NDCG@K 与 RAGAS 生成指标都有基线和趋势。
5. **可私有化、可运维**：容器化部署，支持接入 OpenAI 兼容的自建模型网关，具备限流、缓存、监控与日志。
