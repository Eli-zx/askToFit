## 一、开发环境

### 1.1 依赖

| 组件 | 版本 |
|---|---|
| Python | 3.13+（`.python-version`） |
| uv | 0.9.x |
| Node.js | 20（`.nvmrc`） |
| MySQL | 8.x |
| Redis | 6+ |
| Milvus | 2.4.x（pymilvus 2.4.x） |
| 内存 | 建议 ≥16GB（本地模型 + Milvus 客户端） |

### 1.2 初始化

```bash
cp .env.example .env      # 填数据库、Redis、Milvus、LLM Key
uv sync                   # 运行时 + dev 依赖
cd frontend && npm ci
```

模型目录：

```text
models/bge-m3/
models/bge-reranker-v2-m3/
models/intent-bert/
```

缺失时启动会直接失败（`VALIDATE_MODELS_ON_STARTUP=true`）。

### 1.3 启动

```bash
# 后端（项目根目录）
uv run uvicorn app.main:app --reload --port 8000

# 前端
cd frontend && npm run dev          # 5173，/api 代理到 8000
```

构建预览同样使用 5173（演示域名指向该端口；`strictPort` 保证端口被占时直接报错）：

```bash
cd frontend && npm run build && npm run preview
```

### 1.4 依赖连通

```bash
uv run python scripts/check_services.py
```

## 三、开发流程

项目规则（来自 `CLAUDE.md`）：

```text
理解需求 → 整理方案 → 输出方案 → 等待确认 → 编码 → 写测试 → 跑测试 → 浏览器验收
```

具体要求：

1. **先理解，再方案，后确认**：未获得明确同意前不要写代码；
2. **需求不明必须提问**：描述模糊、缺关键细节、有多种理解、边界不清；
3. **新功能必须写单元测试**：正常路径 + 关键边界；
4. **修改后必须跑测试**；
5. **前端改动必须用浏览器 MCP 实际验证**后再通知验收；
6. **测试全通过后才能通知验收**，通知时说明改了什么、测试结果。

### 3.1 推荐改动顺序

```text
1. 读相关代码与测试
2. 确认数据流：入口 → 服务 → 存储 → 输出
3. 先写/补测试（失败）
4. 最小实现
5. 跑目标测试
6. 跑全量后端测试
7. 涉及前端：跑 Vitest + build + 浏览器验证
8. 更新文档（接口/配置/问题记录）
```

### 3.2 什么时候需要更新文档

| 改动 | 更新 |
|---|---|
| 新增/修改接口 | `docs/接口文档.md` |
| 新增环境变量 | `docs/配置参数手册.md`、`.env.example` |
| 修改链路行为 | `docs/请求全链路详解.md`、`docs/系统架构与数据流.md` |
| 修复真实故障 | `docs/问题与解决方案.md` |
| 修改测试/性能数字 | `docs/测试指标.md` |
| 修改评估口径 | `docs/评估指标.md` |

## 四、代码约定

### 4.1 Python

- 目标 Python 3.13，使用 `from __future__ import annotations`；
- 公共函数写类型标注；
- I/O 一律 `async`，CPU 密集（分词、建索引）用 `asyncio.to_thread`；
- 数据载体优先 `dataclass(frozen=True)`；
- 不吞 `asyncio.CancelledError`；
- 第三方重依赖在函数内懒加载（PDF/Office/OCR/模型）；
- 注释与日志用中文，术语保留英文（BM25、RRF、SSE）；
- 异常信息包含可定位上下文，运维日志带 `文件名:行号`。

### 4.2 错误处理

| 场景 | 做法 |
|---|---|
| 用户输入错误 | `HTTPException(400, "中文提示")` |
| 未登录 | 401 |
| 无权限 | 403 |
| 资源不存在/无权 | 404（不泄露存在性） |
| 冲突 | 409 |
| 限流 | 429 + `Retry-After` |
| 外部依赖失败 | 能降级则降级并记 warning；不能则 `error` 事件/500 |
| 缓存失败 | warning，继续主流程 |
| 指标失败 | 不影响业务 |

禁止：

- 把堆栈、SQL、Key 返回给前端；
- 静默吞异常后返回空结果而不记录；
- 在检索失败时编造答案。

### 4.3 日志

```python
logger.info(
    "回答完成 conversation_id=%d intent=%dms prep=%dms retrieval=%dms "
    "ttft=%dms latency=%dms",
    conversation_id, intent_ms, strategy_ms, retrieval_ms, ttft_ms, latency_ms,
)
```

约定：

- 关键路径用 `info`，详细分支用 `debug`；
- 异常用 `logger.error(..., exc_info=True)`；
- 不打印 token、Key、密码、完整提示词；
- 运维需要定位的日志在消息末尾标注 `（文件:函数）`，同时格式本身已含 `文件:行号`。

### 4.4 数据库

- 使用 ORM，不拼 SQL 字符串；
- 事务边界在路由或服务入口；
- 写路径完成后失效缓存；
- 新增表要在 `app/models/__init__.py` 注册；
- 新增列要同步 `ensure_schema_upgrades`（当前是轻量加法迁移）。

### 4.5 前端

- Vue 3 `<script setup>`；
- Pinia 管全局状态；
- Element Plus 组件 + 手写 scoped CSS；
- 页面容器统一 `.atf-page` / `.atf-page-inner`；
- API 调用集中在 `src/api/`，不在组件里直接写 URL；
- Markdown 必须经 DOMPurify；
- SSE 用 `fetch` + `utils/sse.js`，不用 `EventSource`。

## 五、常见改动路径

### 5.1 新增一个接口

1. `app/schemas/` 增加请求/响应模型与约束；
2. `app/services/` 增加业务逻辑（尽量不依赖 FastAPI）；
3. `app/api/routes/` 增加路由，声明依赖（`get_current_user` / `get_current_admin`）；
4. `app/main.py` 已统一注册路由，确认前缀；
5. 写 `tests/test_*_api.py`：正常、无权限、参数非法、404；
6. 更新 `docs/接口文档.md`。

### 5.2 新增配置项

1. `config.py` 增加 dataclass 字段；
2. 在 `_env_spec` 增加 `字段 -> (环境变量, 转换器)`；
3. 需要范围校验的加到 `_validate()`；
4. `.env.example` 增加说明；
5. `tests/test_config.py` 增加解析与非法值测试；
6. 更新 `docs/配置参数手册.md`。

### 5.3 修改检索

涉及文件：

```text
retrieval.py   召回、融合、缓存、调用重排序
fusion.py      RRF
bm25.py        词法召回
reranker.py    重排序与失败语义
cache.py       缓存键与配置指纹
chat.py        过滤、缺口、meta
```

必跑测试：

```bash
uv run python -m pytest tests/test_retrieval.py tests/test_fusion.py \
  tests/test_bm25.py tests/test_reranker.py tests/test_cache.py -v
```

如果改变排序/过滤，必须再跑检索评估：

```bash
uv run python scripts/evaluate_rag.py --retrieval-only --limit 10 --strategy auto
```

### 5.4 修改重排序

1. `reranker.py` 的候选截断、摘要、打分、失败语义；
2. 保持字段契约：`vector_score` 不被 RRF 分覆盖；
3. 失败时不要静默丢候选，交给 `chat._filter_qualified`；
4. 测试：`tests/test_reranker.py`、`tests/test_chat_service.py`；
5. 性能回归：看 `重排序完成 elapsed=`。

### 5.5 修改提示词

1. 系统提示词在 `app/services/rag.py:SYSTEM_PROMPT`；
2. 意图策略在 `INTENT_GUIDANCE`；
3. 上下文格式在 `format_context`；
4. 不要改变 `sources` 字段契约；
5. 测试：`tests/test_rag.py`；
6. 效果变化用评估集验证，不要只看单题。

### 5.6 新增意图标签

1. `intent.py` 的 `_INTENT_LABELS`、关键词权重、问候正则；
2. `rag.py` 的意图策略；
3. 训练数据逐条手写，重新训练 BERT；
4. `tests/test_intent.py`、`tests/test_intent_pipeline.py`；
5. 评估集 `intent` 字段同步；
6. 前端如有意图展示，更新映射。

### 5.7 新增文档解析器

1. `parsers.py` 增加 `parse_xxx()`，返回 `ParsedDocument`；
2. 在 `parse_document()` 分派；
3. `SUPPORTED_EXTENSIONS`、`allowed_extensions` 同步；
4. `tests/test_parsers.py` 增加正常/损坏/空文件；
5. `docs/接口文档.md` 的 parser 选项更新。

### 5.8 新增缓存层

1. `cache.py` 增加前缀与键函数；
2. 把影响结果的配置加入指纹；
3. 写路径调用 `invalidate_search_caches` 或对应失效函数；
4. 缓存失败必须 warning 后继续；
5. `tests/test_cache.py`。

### 5.9 新增前端页面

1. `views/` 新建页面；
2. `router/index.js` 注册路由与守卫；
3. 需要菜单时改 `components/AppShell.vue`；
4. API 放 `src/api/`；
5. 单测放 `frontend/tests/`；
6. 用 Playwright MCP 验证登录态、空状态、错误态。

## 六、测试

### 6.1 后端

```bash
uv run python -m pytest tests/ -v
```

- 28 个文件、308 个用例，约 38–42 秒；
- 使用内存 SQLite + fakeredis + FakeVectorStore/FakeReranker；
- 不依赖真实模型、MySQL、Milvus、Redis。

测试夹具（`tests/conftest.py`）：

| fixture | 作用 |
|---|---|
| `db_maker` | 内存 SQLite 会话工厂 |
| `fake_redis` | fakeredis 异步客户端 |
| `client` | 覆盖 `get_db` / `get_redis` 的 httpx 客户端 |

写测试原则：

- 断言行为，不断言实现细节；
- 覆盖正常路径、边界值、异常分支；
- 外部依赖用 fake，不打真实网络；
- 异步测试由 `asyncio_mode=auto` 自动处理；
- 新增配置项必须测解析与非法值；
- 权限相关必须测 401/403/404。

### 6.2 前端

```bash
cd frontend
npm run test
npm run build
```

- Vitest + jsdom；
- 8 个文件、56 个用例；
- 重点：SSE 分帧、错误归一化、格式化、API URL/参数、Markdown 安全。

### 6.3 端到端

```bash
cd frontend
```

## 八、前端开发

### 8.1 技术栈

Vue 3.5、Vite 6、Pinia、Vue Router、Element Plus、axios、marked、DOMPurify。

### 8.2 SSE

`utils/sse.js` 负责：

- 按 `\n\n` 分帧；
- 缓存跨 chunk 的半个事件；
- 解析 `event:` / `data:`；
- 忽略注释与空行。

不要在组件里重复实现解析器。

### 8.3 状态与错误

- token 与用户在 `stores/auth.js`；
- 401 由 axios 拦截器统一清会话并跳登录；
- 错误提示通过 `utils/errors.js` 归一化；
- 业务错误优先展示后端 `detail`。

### 8.4 样式

- 页面容器 `.atf-page` / `.atf-page-inner`；
- scoped CSS，BEM 命名；
- 不引入新的 UI 框架；
- 评估看板使用手写 CSS 图表，不引图表库。

### 8.5 路由守卫

- 未登录访问受保护页面 → `/login?redirect=...`；
- 非管理员访问 `/evaluation` → `/chat`；
- 导航项按权限条件渲染。

## 九、日志与错误处理

### 9.1 必须记录

- 请求入口与状态码；
- 外部依赖失败（降级/重试/熔断）；
- 入库阶段与结果；
- 检索召回数、重排序耗时、失败；
- 意图、改写、策略；
- 首包与总耗时；
- 知识缺口；
- 未捕获异常堆栈。

### 9.2 禁止记录

- 密码、密码哈希；
- 完整 JWT / API Key；
- 数据库/Redis 密码；
- 系统提示词全文（debug 也需谨慎）；
- 完整用户回答正文（默认不记）。

### 9.3 错误信息

- 用户可见：中文、可行动、不暴露内部；
- 日志：包含异常类型、堆栈、关键 ID；
- 不要把 `str(exc)` 直接返回前端。

## 十、数据与演示素材

项目硬性要求：

- 训练数据、演示数据、业务文档**逐份手写**；
- **禁止用脚本批量生成内容**；
- 脚本只能做导入、校验、转换，不能编造业务事实；
- 评估集 60 条手写，字段与约束见 `data/evaluation/README.md`；
- 演示文档 9 份，覆盖商品、尺码、物流、退换、发票、支付、会员等主题。

原因：生成内容会出现事实不一致、政策冲突、金额时效错误，直接污染评估与演示可信度。

- **远程推送由项目负责人执行**，开发不要自行 push；
- 若后续启用 git：
  - `.env`、`.claude/`、`models/`、`uploads/`、`logs/`、`reports/` 不提交；
  - 提交前跑全量测试；
  - 提交信息说明“改了什么 + 为什么”；
  - 不提交任何密钥或 token。

代码评审关注：

1. 权限是否正确；
2. 失败是否显式；
3. 缓存是否失效；
4. 是否有测试；
5. 日志能否定位；
6. 是否引入新依赖（尤其是运行时依赖）。

## 十二、常见坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 忘记注册模型 | 表不存在 | 在 `app/models/__init__.py` 导入 |
| 新增写路径没清缓存 | 检索结果旧 | 调用 `invalidate_search_caches` |
| 把 RRF 分当向量分 | 缺口分数失真 | 只读显式 `vector_score` |
| 重排序失败后混用分数 | 排序异常 | 整轮按 `drop`/`vector` 统一处理 |
| 在异步里跑阻塞模型 | 事件循环卡住 | `to_thread` 或线程池 |
| 捕获 `CancelledError` | 客户端断开无法停止 | 重新抛出 |
| 直接比较不同召回分 | 某一路永远赢 | 用 RRF |
| 截断正文再回答 | 块尾答案丢失 | 摘要只用于打分，回答用父块 |
| 新增配置没写 `_env_spec` | 环境变量不生效 | dataclass + `_env_spec` 同步 |
| 配置指纹漏字段 | 调参后仍命中旧缓存 | 加到 `retrieval_config_fingerprint` |
| 删除知识库只删 DB | Milvus 脏向量 | 走 API，先删向量 |
| 前端用 `EventSource` | 无法 POST/带 token | 用 `fetch` + `utils/sse.js` |
| Markdown 直接 `v-html` | XSS | 先 DOMPurify |
| 测试依赖真实服务 | CI 不稳定 | FakeVectorStore/fakeredis/SQLite |
| 日志打印 Key | 密钥泄露 | 只做 set/unset 检查 |
| MinerU 在容器外路径 | 解析失败 | 确认 Docker 与挂载 |
| 多 worker 下 BM25 不一致 | 新文档检索不到 | 单 worker 或缩短 TTL |
